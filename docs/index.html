How it works

From roadmap to release, a pull request at a time.

Run each step yourself, or let autopilot work through a milestone: it builds the next issue, and each devops shift reviews, fixes and merges, until the lead says the milestone is done. Every plan starts from your product’s vision, in VISION.md.

PlanThe team agrees a roadmap; items become issues
BuildThe lead plans, builders write the code
TestEvery round, in a sandbox if you like
CheckThe app is used like a user would, before and after
ReviewThe lead reads files and runs tests itself
FixRequested changes go back to the builder
MergeOnly with green CI and every approval
ReleaseAutomatic, or when you approve it
The team learns: reviewers’ lessons go into every later prompt, and the surest become rules. ·A scoreboard shows what each member costs and how often it’s approved first time.

Behaviour checks

Tested the way your users will use it.

Tests check what their authors thought of. Every build round, REA uses the program like a user would, on the version the work started from and with the changes, and the lead reviews what a user would notice, with the screens as evidence.

terminal

Command-line programs

The commands run in a real terminal, with typed input. The final screen, the exit code and the files left behind are compared.

browser

Web apps

The app is started and a browser follows plain steps like click button "Start", each with a deadline. The page as a screen reader sees it, errors and a screenshot are compared.

electron

Desktop apps

An Electron app is started and clicked through. Its windows, the IPC channels it uses and the external effects it attempts are compared.

api

Libraries

The public API of a built .NET assembly or a JavaScript package. A removed or changed member breaks callers, and releases follow it.

Know-how for every member, from day one.

Guardrails

Rules in code, not in prompts.

Models are asked nicely; the tools they act through check. A shift can’t merge what the rules don’t allow, whatever the model says.

✓

Approvals tied to a commit

Green CI, the lead’s approval and every owner’s sign-off, all on the exact head commit. A new commit needs them again.

◆

You decide what matters

Paths like auth/ or dependency files wait for your approval, and releases can too.

▣

Sandboxed tests

The code the team writes runs in a throwaway container, with no network and none of your keys.

⚿

No secrets pushed

Every push is scanned for keys, tokens and private keys first. Keys stay in your environment.

$

Spend limits

Per run, per day and per milestone, checked before every model call, with an estimate before you start.

⌧

Outside text is data

Issues, PR text, comments and tool results reach the models marked untrusted, never as instructions.

#

Versions follow the API

A release smaller than the public API’s changes allow is refused: removing a member needs a major version.

⌕

What ships is checked

The security member also reviews the build output: credentials, internal addresses and source maps.

≠

Checks can’t be weakened

A member can’t loosen a linter or formatter config to make a check pass; it fixes the code instead.

?

Facts before sensitive changes

CI, migrations, auth, payment, secrets and deployment files change only after the member says what uses them, what could break and how it’s checked.

◇

The team’s own setup, audited

Prompts, skills, agent files, tool servers and permissions are checked for injected instructions, open permissions and secrets.

◎

Observe, never copy

Tools that look inside other software never reach the members who write code. The scout only looks from outside.

The desktop app

Your team and Claude, in one app.

LakebaOS for macOS and Linux puts every project’s team, runs, spend and approvals in native windows, next to a chat with Claude that knows your project. Looking around costs nothing: the screens talk to agent-team on your machine, and only the chat uses Claude. Approvals stay yours, each one confirmed.

Your team at a glance

Members and their models, a readiness checklist with fixes, what’s running, spend today against your limit, changes not kept yet, and the schedule for the devops shift.

Runs in plain words

Start a run with its cost estimate first. While it works, a plan box tells what the team is doing; when it ends, a recap with next steps. A run refused at the spend limit can wait for the limit to reset.

Approve and review

Pull requests and releases that wait for you, each approved after a confirmation. Read a pull request’s changes, comment on lines, and have the team fix them.

Chat about a project

A chat can belong to a project: Claude follows its instructions, reads its files (read-only) and starts runs with your approval. It can’t merge, release or approve.

Projects on other machines

Add a computer you reach with SSH, like a Linux box or a VM, and its projects open in the same windows. Your keys stay in SSH; nothing to install on this side.

Made for the desktop

A menu-bar status, notifications when a run ends or something waits for you, links that open a project on a tab, memory you can edit, and charts in Claude’s answers.

Download

macOS, Apple silicon macOS, Intel Ubuntu / Debian (x64) Ubuntu / Debian (ARM)

Needs agent-team 0.13.11 or newer (pipx install agent-team), and your own Anthropic API key for the chat. Other Linux: the AppImage for x64 or ARM. On Linux, install the .deb with sudo apt install ./lakebaos-client_amd64.deb; the app updates itself.

macOS: this first version isn’t signed yet. The first time you open it, macOS says it can’t check it: open System Settings › Privacy & Security, find the message about LakebaOS Client and choose Open Anyway. Until it’s signed, update it by downloading it again. Release notes.

Developers: run it yourself

Three commands to a working team. macOS or Linux with Python 3.11+ and git. GitHub’s CLI for the pull-request workflows. An Anthropic key only if members use Claude. Node.js 22+ if you want behaviour checks (REA).

Try it first, in a minute

A two-member team adds a feature to a small sample app in a throwaway folder: plan, code, tests, review. It uses Claude if you have a key, a local Ollama model if you have one, or a recorded run that needs nothing at all.

Questions

Frequently asked

Do I need to know how to code?

No. You describe what you want and approve each step. The AI team writes the code. Until the hosted service opens, you install it on your computer: on a Mac, download it and double-click, and a guided setup does the rest.

Is it really free?

Yes. agent-team is open source under MIT. The hosted Lakeba OS build service, coming soon, will be free, with a fair-use build allowance per idea.

Who owns my MVP?

You do. If Lakeba co-founds your company, the MVP is transferred into that company, which you and Lakeba own together.

Is funding guaranteed?

No. Lakeba reviews every application and funds a limited number of ventures. Every applicant keeps their MVP whatever the outcome.

Can I use agent-team without applying?

Yes. It is open source and runs on your machine with the models you already have.
